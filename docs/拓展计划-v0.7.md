## 二 项目定位与判断

### 2.1 已经站住的三条叙事

PLAN §1.2 的简历叙事目前依然成立且被实现证实：

| 作品 | 形态 | 证明能力 |
|---|---|---|
| GitHub-ZH-Plugin | 油猴脚本 | 前端、浏览器生态、CI |
| codingagent | Next.js 全栈 | 全栈、AI 应用、产品化 |
| **repo-ai-cli** | **npm CLI** | **Node 生态、CLI 工程、npm 发布、LLM 工程化** |

三作品闭环「浏览器端 → Web 全栈 → 开发者工具链」覆盖三种主流交付形态，这是该项目在简历上的核心价值，后续拓展应继续加深 CLI 这一端。

### 2.2 当前真实处境

按实测数据，项目处在「**工程完善但采用停滞**」的阶段：

- 工程面已经很扎实：242 测试、严格类型、CI 门禁、doc 一致性检查自动在跑
- 采用面几乎为零：月下载 71（其中相当比例是开发期安装），无 star、无 issue 反馈
- **继续堆命令数对采用几乎没有边际收益**——目标用户（一个想快速生成 README 的开发者）不会因为第 24 条命令而改变选择

### 2.3 拓展原则（本计划的取舍依据）

1. **不再横向铺命令**，转纵向提升「生成质量」与「上手成功率」——后者是被采用的前提
2. **先修发布链路**，否则任何新功能都到不了用户手里
3. 每一项动源码的拓展都必须有验收命令与回归测试，延续现有门禁标准
4. 文档与代码口径必须同步（本仓库已有 `docs:check` 把守 CLI surface，不能让它形同虚设）

### P1-1 生成质量：README 输出的结构化校验

- 问题：目前 README 生成后直接落盘，没有对「有没有生成出标题段、有没有明显编造」做校验
- 做法：落盘前做轻量结构检查（至少含一级标题、含功能章节、不含「TODO」以外的占位符残留）；不合格则报错而不是写出半成品
- 验收：用 4 个本地仓库分别跑 `readme --dry-run`，再 mock LLM 输出验证校验分支

### P1-2 上手成功率：首跑引导

- 问题：一个全新用户没有配置任何 key 时，第一条命令大概率得到一段英文报错
- 做法：无 key 时直接提示三条可选动作（配 DeepSeek / 本地 Ollama 免 key / 任意 OpenAI 兼容端点），并给 `doctor` 入口；这是全项目投入产出比最高的一项
- 验收：清空 key 后跑任一 AI 命令，断言提示里出现上述三条

### P1-3 离线能力扩充（低风险、纯本地、可测）

| 方向 | 说明 |
|---|---|
| `changelog --format` | 支持 Keep-a-Changelog 之外的 compact 输出（适合 CHANGELOG 已经很长的项目） |
| `stats --since` | 按时间窗口统计提交与贡献者 |
| `gitignore --list --json` | 补齐 JSON 输出（目前 `--list` 只有文本） |

### P2-1 原路线图仅剩项：GitHub PR review

- PLAN §11 表中仅剩的未完成方向
- 依赖 `gh` CLI（目前仓库已有 `pr --create` 调用 `gh pr create`，有现成调用路径）
- 动作：`review-pr <url>` 拉取线上 PR diff 复用现有 review 命令的 prompt 与分级输出

### P2-2 采用面（非代码）

## 附录 B 安全修复的冒烟步骤

```bash
# 密钥值走环境变量，写死在文档里容易被误当成真实凭据复制
D_APP_TOKEN="abcdef1234567890"
D_APP_PASSWORD="hunter2secret"
D_API_KEY="ghi5678jklmno0123"

D="$TMPDIR/smoke-target"
mkdir -p "$D"
# Windows 下 TMPDIR 与 node 的解析可能不一致，若报"路径不存在"改用下一行
# D="$LOCALAPPDATA/Temp/smoke-target"
printf 'K=1\n' > "$D/.env"
printf 'TOKEN=%s\n' "$D_APP_TOKEN" > "$D/app.env"
printf 'password: %s\n' "$D_APP_PASSWORD" > "$D/config.yaml"
printf '{"apiKey": "%s"}\n' "$D_API_KEY" > "$D/service.json"
printf '# Demo\n' > "$D/README.md"
printf 'export const a = 1;\nconst k = options.apiKey;\n' > "$D/app.ts"
printf 'K=YOUR_KEY_HERE\n' > "$D/.env.example"

cd E:/repo-ai
node dist/index.js readme "$D" --dry-run                 # 应逐条 warn 四个敏感文件，collected 3
node dist/index.js readme "$D" --dry-run --json          # stdout 应只有 JSON，无告警噪音
```
