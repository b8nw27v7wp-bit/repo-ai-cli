## 三 本轮改了什么（按主题，不按提交顺序）

### 3.1 命令层测试（v0.8 P0-1）

`test/` 下新增 19 个测试文件 + 共用脚手架 `test/helpers/command-harness.ts`（LLM 打桩 / stdio 捕获 / 临时 git 仓库）。覆盖的固定四点是：非法参数退出码 1、`--json` 下 stdout 纯净、失败不写半成品、`-o` 落盘路径。

**这批测试抓出了一个真 bug**（见 3.5）。

### 3.2 参数命名统一（v0.8 P0-2）

`--max-tokens` → `--budget-tokens`（readme / ask / fix）、`--max` → `--max-commits`（changelog）。旧名保留为**隐藏别名**，命中时向 stderr 打一行 deprecation 警告，新旧同时给出时以新名为准。实现见 `src/lib/options.ts` 的 `DEPRECATED_ALIASES` / `applyDeprecatedAliases`，挂在 `src/cli/program.ts` 的 preAction 钩子上（一处覆盖 4 条命令）。

**用 `minor` 而不是原计划的 `major`**：旧名仍可用，运行时向后兼容，按 semver 不算 breaking。见 `.changeset/unify-budget-flags.md`。

### 3.3 CLI 组装层拆分（v0.8 P1-1）

```
src/index.ts        859 行 → 10 行
src/cli/program.ts         program 组装 + 全局 option + preAction 钩子 + COMMAND_ORDER
src/cli/register-ai.ts     12 条 AI 命令（一命令一注册器）
src/cli/register-offline.ts 12 条离线命令（含 hooks / config 子命令组）
src/cli/shared.ts          withLLMOptions / handleError / resolveNumber
```

`src/cli/program.ts` 里的 **`COMMAND_ORDER` 是 `--help` 的展示顺序，也是 README「Command Options」的小节顺序**，两者必须一致。拆分时为了保住「纯搬迁」才显式写死顺序——按「AI 命令整块在前」的自然拆法会改掉它，就不是可证明的无副作用重构了。验证方式见 3.4。

### 3.4 dist 级端到端基线（v0.8 P1-2，v0.9 扩充）

`scripts/e2e-smoke.mjs` + `npm run e2e`，当前 **31 项**。全程离线、隔离 HOME、清空全部 provider key，所以结果与跑它的机器无关。覆盖：CLI surface、离线命令 JSON 契约、参数改名、配置默认值、**LLM 完整链路（本地假端点）**、无 key 首跑引导、各类失败路径。

两条值得记住的能力：

- **本地假 LLM 端点**（脚本内 `createServer`）：能看见工具**实际发出去了什么**（temperature / max_tokens 是否采纳了配置），也能断言 token 用量。没有它，「配置被采纳」只能靠人肉读代码。
- **`--help` 逐字节 diff**：拆分前后各抓一次顶层 + 33 个叶子命令的 `--help`，diff 无输出即证明零行为变更。比「跑一遍 e2e 没报错」强——e2e 只覆盖断言到的那几条。

另加了 `pree2e` 钩子：`npm run e2e` 现在总是先构建，不会跑在过期 dist 上（这是本次开发中踩过两次的坑）。

### 3.5 配置层收口（v0.9 P0-1）

**这是本轮最有价值的一块。** 修的问题：`config set maxTokens | maxFileKb | maxDiffKb | maxOutputTokens | temperature` 五个键此前是**只写键**——保存成功、`config list` 显示、`config.ts` 的 label 写着用途，但没有任何命令读取。用户以为设了默认值，实际命令仍走各自的 flag 默认值，且无任何提示。

改法：配置解析整体上移到 CLI 层，命令层只接收解析后的选项。

```
规则：命令行显式给出 > ~/.repo-ai/config.json（含激活 profile） > 内置默认值
```

- `src/cli/shared.ts` 的 `resolveNumber(cmd, opts, key, cfgValue)` 是这条规则的唯一实现
- 12 个 AI action 各加 `const cfg = await loadConfig(opts.profile)`，数值项走 `resolveNumber`，并把 `resolvedConfig: cfg` 传给命令
- 12 条 AI 命令删掉 `await loadConfig(options.profile)`，改用 `options.resolvedConfig ?? {}`
- **内置默认值不重复写**：commander 的默认值已经在 `opts[key]` 里，`resolveNumber` 直接用它，避免同一个数字出现在两处后漂移

`src/types.ts` 同时抽了 `AiCommandBase`（provider / baseUrl / model / apiKey / profile / maxOutputTokens / temperature / json / resolvedConfig），消掉 12 个接口里 96 处逐字重复字段。

### 3.6 LLM 调用收尾抽取（v0.9 P0-2）

`src/lib/llm-step.ts` 提供 `callLlmOrFail` 与 `streamLlmOrFail`。空响应守卫从 10 处收敛到 1 处（`EMPTY_RESPONSE` 常量），AI 命令合计 1651 → 1565 行。

**刻意没抽的**：命令的输出尾巴（`-o` 落盘 / JSON / stdout 三选一）。同一个命令「有 `-o`」与「无 `-o`」两个分支的 JSON 字段都不一样（`test` 无 `-o` 时给 `content`、有 `-o` 时给 `output`），抽出来要传一堆参数，比重复更难读。理由写在 `llm-step.ts` 的注释里。

### 3.7 token 用量可观测（v0.8 P1-3）

`src/lib/usage.ts` + `llm.ts` 的两条路径。非 JSON 向 stderr 打一行汇总，JSON 并入 `usage` 字段；缺失时给 `null`/「未知」而**不猜 0**（「未知」与「0」对按量付费的用户是两个完全不同的信息）。不做价格换算。

### 3.8 review-pr 回写评论（v0.8 P2-1）

`--comment` / `--yes`。默认只预览；需要 `GITHUB_TOKEN`；Critical/Major 各占一条评论，Minor/Nit 与总述合并成一条；TTY 下即使带 `--yes` 仍再确认一次。分级解析在 `src/lib/review-parse.ts`（按 markdown 标题切块 + 识别级别关键词，兼容 emoji / 中文 / 任意标题层级）。

### 3.9 覆盖率基线（v0.9 P1-1）

`@vitest/coverage-v8` + `npm run coverage` + `npm run coverage:report`。阈值钉在基线下方约 2 个点（**只防回退，不设达标线**——追求好看的百分比只会诱导写出「为覆盖而覆盖」的用例）。CI 用 `coverage` 代替 `test`：同一次运行，外加阈值。

## 六 踩过的坑（下次别重复）

1. **`spawnSync` + 同进程 HTTP 服务器 = 死锁。** `scripts/e2e-smoke.mjs` 的假 LLM 端点跑在脚本进程里，而 `spawnSync` 阻塞事件循环，子进程的请求永远等不到响应。改用 `promisify(execFile)`（异步，事件循环空闲）。
2. **改完 `src` 一定要重建再跑 e2e。** 已被误导两次。现在有 `pree2e` 钩子兜底，但手动 `node dist/index.js` 探测时仍要注意。
3. **`rm -rf "$HOME"` 会被安全检查拦下**（它把 `$HOME` 解析成真实用户目录）。验证隔离 HOME 时用 `mktemp -d` 建全新目录，不要删。
4. **commander 的 `setOptionValue` 不设置来源**，`getOptionValueSource` 会返回 `undefined`。凡是需要在「用户显式给出」与「默认值」之间区分的场景，必须用 `setOptionValueWithSource(key, value, "cli")`。
5. **commander 的 `--help` 默认值由 option 声明决定**，`resolveNumber` 依赖这一点（内置默认值只写在 CLI 层一处）。如果把默认值从 option 上摘掉挪进命令层，会同时改掉 `--help` 的输出。
6. **`test/helpers/` 不会被 vitest 收集**（`include: ["test/**/*.test.ts"]`），可以安全放辅助代码。

## 七 本仓库的既有约定（新人容易忽略）

- **`docs:check` 会把 README 与真实 `--help` 对齐**：加命令、加 flag、改命令总数（`src/cli/program.ts` 的 description）都必须同步 README，否则 CI 红；`####` 小节的**顺序**也必须与 `--help` 一致，新增命令时别把 README 小节插到末尾。
- **stdout 只放产物，状态与进度一律走 stderr**（`src/lib/ui.ts`）。`say` / `warn` / `done` 在 JSON 模式静默，`console.log` 才是产物通道。
- **失败不写半成品**：落盘前校验（`readme-validate.ts`）、原子写（`lib/output.ts`）、失败路径不留已改的文件（`release` 的教训）。
- **每个改动都要有可复现的证据**：两轮计划文档里的每个数字都带产生它的命令，附录 A 可直接复制执行。
- **改行为要配 changeset**（`.changeset/*.md`），`minor` / `patch` 的取舍见 3.2 的说明。
- **测试要能变红**：新增用例至少做一次变异验证（改坏实现看是否变红），两轮工作的计划文档里都记了具体做法。
